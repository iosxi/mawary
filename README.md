# mawary

**スマホの背面を向けた方角に何があるか**を、一人称視点で出す Android アプリ。
地図を見下ろすのではなく、**自分がその場に立っている**という見え方をする。

- 対応: Android 9 (API 28) 〜 最新 (targetSdk 36 / Android 16)
- 出来上がり: `mawary.apk` — **約 59 KB**
- 要求する権限: **`INTERNET` と `ACCESS_FINE_LOCATION` の 2 つだけ**
- 依存ライブラリ: **無し**（AndroidX も Play 開発者サービスも使っていない）
- **API キーは要らない。** 入れなくてもそのまま使える

> **実機で確認済み。** Sony XQ-FS44 / Android 16 (API 36) に入れ、実際の現在地で
> 周りの店や施設が出るところまで見ている。測った値は下の「実測」に載せた。

## 画面

画面そのものが**自分の視界**。

- **左右は方角。** 背面が向いている先が画面の中央で、**正面 180 度**が画面の幅に
  ちょうど収まる。背後にあるものは出ない。
- **上下は距離。** 足元が下、レンジの端が上（地平線）。地面は遠近法どおり、
  地平線は真っ直ぐで、**手前ほど端が大きく下に垂れる**。
- 地平線の上に **北 / 北東 / 東 …** が立っていて、これが方角の目印になる。北は赤。
- **モノは地面に刺さった杭**として出る。杭の足元がその場所。
  画面に入ったものは全部オレンジで、名前と距離の**札**が付く。
  札は杭の上には置かず、**杭の周り 8 方向（上下左右と斜め）× 7 段階の距離**から選ぶ。
  札は**漫画の吹き出し**の形で、札の向かい合う辺（斜めなら角）から杭の頭の真ん中へ
  尻尾が伸びる。枠と尻尾はひとつながりの輪郭なので、どの線がどの札のものかで
  迷わない。尻尾は根元 6dp の細い楔で、先へ向かって尖る。枠は地面の線より一段明るい色。
  - **線はなるべく短く。** 札が別の杭のそばにあって線だけ遠くへ伸びていると、
    どの杭の札か取り違える。だから線の長さをいちばん重く数え、
    **線どうしの交差**と**線が他の札を横切る**ことにも罰を付ける。
    少しの重なりを避けるために札を遠くへ飛ばすことはしない。
  - 置き方は点ラベル配置問題（Christensen・Marks・Shieber の焼きなまし法で
    知られる）の決定的な版。**近い順に貪欲に置いたあと、全部の札を「他の札が
    今ある場所」を前提に最良の場所へ置き直す**のを 3 周回す。焼きなましは乱数を
    使うので、毎フレーム少しずつ違う配置になって札がちらつく。
  - 範囲表示（右端の「1.0km」）の上にはまず置かない。
  - 置き場が足りなければ重なるのは仕方ないとし、**重なったら近いほうが上**。
  - 向きを少し変えたくらいで札が跳ね回らないよう、前の場所に居座る方を少し優先する。
  - 札の地は**透過度 66%**（既定）。設定画面で 0〜100% を 1% 刻みで変えられる。
  - 札を出すのは近い順に 30 件まで（杭は全部出る）。
- 下の**一覧**には、**正面 180 度にあるもの全部**が近い順に並ぶ。
  見えているのは **3.5 行**で、**上下に指で送れる**（半端な 3.5 行なのは、
  下に続きがあることが一目で分かるようにするため）。右に細いバーが出る。
  名前と距離、それに `<` `>` `|` で**どちらへ振れば正面に来るか**。
  名前は切らずに、**入る大きさまで文字を縮めて**出す（「ファミリーマート○○店」の
  後ろが消えると、どの店か分からなくなるため）。

### 自分の立ち位置 — 方位磁石

画面の下の方にある**厚みのある方位磁石**が自分自身。中心が自分の立ち位置。
小さく描いてある。方位磁石は「自分がどこを向いているか」であって、
**見に来たもの（検索結果）ではない**ので、譲れる場所は全部そちらに渡している。

- **赤い針が北。** スマホを回せば針が回る。
- **傾きが形に出る。** 水平に構えると、寝かせた磁石を真横から見ることになるので
  **細い隙間になり、代わりに側面（厚み）がいちばん厚く見える**。
  下に向けるほど**円に開き、側面は消えていく**。数字を読まなくても傾きが分かる。
- 透けない。地面の線は磁石の手前に出ない。

正直な遠近法だと水平時に完全な線へ潰れるが、潰れた瞬間に何も読めなくなるので、
開き具合には下限を置いてある。

### 検索

右上の**虫眼鏡ボタン**を押すと、何を探すかを入れられる。入れると**その言葉に合うものだけ**
が画面に出る。入っている間は虫眼鏡と画面上部の言葉に色が付く。「空にする」で戻る。

枠には薄く「検索ワード」とだけ出る（見本の語を入れておくと、既に何か入っていると
読めてしまうため）。既に言葉が入っているときは**全選択した状態で開く**ので、
そのまま打てば置き換わる。

**開いた時点で枠にフォーカスが当たり、キーボードも出ている。** ここは一度
外している。選ぶだけでは駄目で、フォーカスの無い枠は選択を描かないので
**何も見えず**、キーボードを出すには枠を押すしかなく、**その一押しで選択が
消える**。キーボードまで出して初めて、全選択が見えて、かつ役に立つ。

言葉の扱いは 2 通り。

- **知っている言葉は、地図のタグに読み替える。** 「山岳」なら `natural=peak`、
  「駅」なら `railway=station`。**名前だけを引いても役に立たない**のがここの
  理由で、探している山の名前を知っているなら、そもそも探していない。
  `peak` `station` `cafe` のような英字でも引ける。いま読み替える言葉:

  | 言葉 | 出るもの |
  | --- | --- |
  | 観光 / 名所 / みどころ | 観光地・展望・博物館・遊園地・動物園・水族館 |
  | 景勝 / 絶景 / 展望 / 眺め | 展望地・山・滝・観光地 |
  | 史跡 / 旧跡 / 遺跡 / 歴史 | 史跡いっさい |
  | 博物館 / 美術館 / 資料館 | 博物館・美術館・屋外の作品 |
  | 遊園地 / 動物園 / 水族館 | それぞれ |
  | 滝 / 川 / 湖 / 池 / 島 / 城 | それぞれ |
  | 海水浴 / ビーチ / 砂浜 | 浜 |
  | 山岳 / 峰 / 登山 / 山 | 山頂・火山 |
  | 温泉 / 銭湯 / 風呂 | 浴場 |
  | 駅 / 鉄道 | 駅 |
  | コンビニ / 店 / 買い物 | 店 |
  | 食事 / レストラン / 飯 / 食堂 | 飲食店 |
  | カフェ / 喫茶 | 喫茶店 |
  | 公園 / 学校 / 大学 / 病院 / 医院 | それぞれ |
  | 寺 / 神社 / 教会 | 宗教施設 |
  | ホテル / 宿 / 旅館 | 宿 |
  | 銀行 / 郵便 / トイレ | それぞれ |

  この表は当て推量ではなく、札幌・京都・箱根の 3 か所で**実際にタグに何件
  入っているか数えてから**決めた。たとえば「温泉」は `natural=hot_spring`
  では 3 か所とも **0 件**で、`amenity=public_bath` にすると 46 / 26 / 9 件
  だった。
- **知らない言葉は、名前そのものを引く。** Overpass の正規表現検索に渡す
  （渡す前にメタ文字は無効化する）。店名の一部を入れればそれが出る。

キーを入れてある場合は Google Places の Text Search に同じ言葉を渡す。

### 検索が速いのは、たいてい何も訊いていないから

**検索は、ほぼその場で出る。実測で 1 秒。** 速さの出どころは、通信を速くした
ことではなく、**通信しないで済ませていること**。

起動時に取ってくる「周りのもの一通り」は、画面に出す 40 件ではなく
**取れただけそのまま持っておく**（Photon から 140 件前後）。検索語が来たら、まず**その手持ちの中から**
名前で、あるいはタグで拾って**すぐ出す**。そのうえで本来の問い合わせも投げ、
返ってきたら差し替える。画面には出している間だけ
「手元の範囲から表示中。照会しています…」と出る。

そのために、持っているものには**OSM のタグのキーも一緒に覚えてある**
（`shop` なのか `amenity` なのか）。「店」のようなタグに読み替わる言葉も、
これで手元だけで拾える。

残りの手当ても実測に基づく。

- **`nwr` で書く。** 同じ範囲・同じ結果を、node と way に分けて 10 文で書くと
  12.0 秒、`nwr` 6 文で書くと **3.2 秒**だった。node / way / relation を
  1 文で扱えるぶん、Overpass の仕事が減る。
- **待たずに 2 本目を出す。** 1 本目に 2.5 秒の先行を与え、まだ返って
  こなければ 2 本目を並行して投げる。**健全な応答は 2〜3 秒、拒否は 9〜11 秒**
  なので、拒否を待ってから次に行くと、それだけで 10 秒を捨てることになる。
  同時に動かすのは 2 本まで（Overpass が求めている上限）。
- **毎回違うエンドポイントから始める。** 3 つはレート制限を共有していない。

### 操作

- **右端の縦スライダーで距離レンジ**
  （100m / 200m / 500m / 1.0km / 2.0km / 5.0km / 10km）。
  上が遠く、下が近く。画面の上下方向の意味と揃えてある。
  **指を離したときに 1 回だけ**検索し直す（段ごとに検索を投げない）。
  山を探すなら 2km では届かないので、遠い側を広く取ってある。
- **右上に 2 つのボタン。** 左が**虫眼鏡（検索）**、右が**歯車（設定）**。
  どちらも 48dp 四方で間は 8dp、押している間は色が変わる。指を離したときに
  ボタンの上にあるときだけ効くので、ずらせば押すのをやめられる。
- **設定は全画面。** 歯車を押すと切り替わる。
  - 「ラベルの透過度」: スライダーの下の見本がその場で変わる。動かすとすぐ保存。
  - 「Google Places API キー」: 画面を離れるときに保存。
  - 一番下に**情報源**（OpenStreetMap / Google マップ）、**測位の精度**、
    **バージョン**。以前は本画面の下端に常に出していたが、いつも見るものでは
    ないのでここへ移し、その分を視界と一覧に回した。
  - 戻るのは左上の ← か、端末の戻る操作。
- **方位の校正が要るときと、検索がつまずいたとき**だけ、視界の上に一行の
  お知らせが出る。何も無いときは出ない。
- **探している間は、視界の真ん中にスピナー**が回る。カードに載せてあるので
  札の上でも読め、下に「探しています…」や、どのサーバに聞いているかが出る。
  回っている間だけ画面を描き直し、終われば止まる。
- **タップは何もしない。** 後で別の用途に使うため空けてある。
- **一覧は上下に送れる。**

画面は消灯しない。回転もしない（縦固定）。
**下のシステムボタン（ナビゲーションバー）は隠さない。** 隠すと戻るもホームも
押せなくなるうえ、その帯は元々使っていない。上のステータスバーだけ伏せている。

## 背面の方角の出し方

このアプリの肝。**傾けても読みが飛ばない**ようにしてある。

素直に作るなら、端末の -Z 軸（背面カメラが覗いている向き）を水平面に落として
方位を取る。ところが**スマホを寝かせると -Z は真下を向く**ので、水平成分は
ただの雑音になる。よくある対処は「傾きが閾値を超えたら +Y 軸（上端の向き）に
切り替える」だが、**切り替わる瞬間に読みが飛ぶ**。

mawary は閾値を使わない。**-Z と +Y の水平成分を、正規化せずにそのまま足す**。

- 立てて持つと -Z がほぼ全部を担い、+Y は真上を向くので水平成分がほぼ 0。
- 寝かせると役割がそっくり入れ替わる。
- その中間では**両方とも同じ方位を向く**ので、足して困らない。

正規化しないことが、そのまま「水平に寝ている軸ほど強く効く」重み付けになる。
2 軸は直交しているので**同時に真上を向くことはなく**、和が消えることもない。
（[`Geo.backAzimuth()`](app/src/main/java/com/mawary/Geo.java)）

**実測で裏を取ってある。** 姿勢行列を組み立てて JVM で回し、

- 手で組んだ 4 姿勢（立てて北 / 立てて東 / 寝かせて上端が北 / 寝かせて上端が西）が一致
- 方位 7 通り × 傾き 7 通り = **49 通りすべてで、狙った方位を 0.5 度以内で復元**
- 立てた状態から寝かせるまで 0.5 度刻みで掃いて、**隣り合う読みの差の最大が 0.0000 度**
  （＝どこにも飛びが無い）

読みは角度そのものではなく**単位ベクトルのまま平滑化**している。
359 度と 0 度をまたぐときに暴れないため。

## 電池と、固まっていた原因

**v2 までは固まることがあった。** 実機の ANR 記録を読むと、入力待ちで
5 秒を超える直前まで**メインスレッドが 95% の CPU を焼いていた**。
測ってみると原因ははっきりしていて、**方位センサが毎秒 54 回届き、その全部で
画面を描き直していた**。静止していても、である。

直したのは次の 4 か所。電池の話と、固まる話は同じ話だった。

1. **変化していないなら描かない。** 方位が 0.4 度、傾きが 0.8 度動いていなければ
   その読みは捨てる。実測で、**据え置いたまま 20 秒で描画 0 フレーム**
   （以前は同じ 20 秒でおよそ 1080 フレーム）。
2. **ジャイロを止めた。** 方位は `TYPE_ROTATION_VECTOR` ではなく
   **`TYPE_GEOMAGNETIC_ROTATION_VECTOR`** から取る。加速度計と地磁気だけで
   同じ姿勢行列が得られ、**ジャイロを回さずに済む**。
   `dumpsys sensorservice` の active sensors からジャイロが消え、
   `sns_geomag_rv` に替わったことを実機で確認している。
   無い端末では従来のものに落ちる。
3. **センサの配信を 54 Hz から 30 Hz に落とした。** 人が読む方位計に
   毎秒 54 回は要らない。1 回ごとにアプリケーションプロセッサが起きる。
4. **測位を 2 秒/5m から 4 秒/12m に緩めた。** 検索はレンジの 1/4 動くまで
   走らないので、それより細かい更新は捨てていただけだった。
   Android 12 以降は省電力の `FUSED_PROVIDER` を使う。

あわせて、**許可ダイアログの出し直しループ**も直した。以前は `onResume` のたびに
権限を要求していたので、一度断ると**アプリに戻るたびにダイアログが出て**、
操作不能に見えた。要求は 1 回だけにしてある。

画面を点けたままにするのは仕様（歩きながら見るため）なので、
残る最大の消費はディスプレイそのもの。

## どこから「モノ」を取るか

**既定は「キー無し」。** そのまま入れて、そのまま使える。
情報源はすべて OpenStreetMap のデータで、API キーも登録も要らない。
このリポジトリの実機確認も、すべてキー無しで行っている。

問い合わせ先は 3 つあり、**得意なことが違うので用途で使い分けている**。
どれを選ぶかは、同じ地点・同じ質問で測ってから決めた。

| 用途 | 使うもの | 実測 |
| --- | --- | --- |
| 周りのもの一通り / 言葉をタグに読み替えた検索 | **Photon** | 2 秒前後、**5 連投しても全部 200、拒否ゼロ** |
| 名前の一部での検索 | **Nominatim** | 0.2〜1.6 秒、**無停止 4 連投でも全部 200** |
| 名前の一部での検索（取りこぼし時） | Overpass | 2〜12 秒、**拒否が多く、拒否と分かるまで 9〜11 秒** |

### Photon — 周りを見るのはこれ

`photon.komoot.io`。OSM を検索索引に載せたもの。**拒否してこない**のが最大の
取り柄で、そこが Overpass との決定的な差になっている。

ただし癖が 2 つある。

- **1 回につき 50 件しか返さない。** 何件と頼んでも 50。だから「全部まとめて
  1 回」だと 50 件目までしか届かず、市街地では **580m** で打ち切られて画面の
  奥半分が空になる。**種類ごとに分けて投げる**と種類ごとに 50 件貰えるので、
  同じ場所で **2km・180 件**まで届いた。投げる先は互いに独立なので同時に出す。
- **語の検索は前方一致。**「マート」で「マート島桝店」は出るが
  「セイコーマート」は出ない。人が探すときと逆なので、語の検索はここへは送らない。

### Nominatim — 名前の一部で探すのはこれ

OSM 本家の検索。**語の中ほどにも当たる**ので「マート」で「ファミリーマート」が
出る。ここが Photon との違い。無停止で 4 回投げても全部 200 で返った。

万能ではない。**トークン単位**なので「セイコー」では 0 件になる（「セイコーマート」
が 1 語として入っているため）。そこで当たらなければ Overpass に回す。
1 文字も同じで、「木」では「創成材木店」に当たらない。しかも**語を含まない
ものを返してくる**ことがあり、「木」には平岸霊園・月寒墓地・白石本通墓地の
3 件が返った。何か返ると Overpass に進まないので、**名前に検索語を実際に
含むものだけを残し**、残らなければ Overpass に回す。

先方の規約が「1 秒に 1 回まで、名乗ること」なので、**呼ぶのは利用者が検索を
確定したときだけ**にして、間隔も空けてある。

**距離順ではなく先方の「重要度」順で、上限の件数で打ち切られる。** 範囲を広げると
遠くの当たりで上限が埋まり、近くのものが押し出される。実測で「窓」は、5km の
箱では 8 件（全部 5km 以内、最寄り 772m）、10km の箱では上限の 40 件で
**5km 以内が 0 件**（最寄り 5.9km）だった。上限を先方の最大の 50 にしても同じ。
そこで、**返ってきた件数が上限ちょうどなら箱を半分にして聞き直し**、上限に
届かない答えが返るまで繰り返して合わせる（最小 500m、最大 5 回）。上限に届かない
答えはその箱の中を取りこぼしていないので、近い側が必ず揃う。「窓」の 10km は
2 回で済み、合わせて 48 件、近い順 40 件に 5km 以内の 8 件が全部残った。

### Overpass — 最後の砦

名前での検索は、店・施設などの種類が付いたものと駅に加えて、**名前の付いた
建物**も対象にしている。「創成材木店」は `building=yes` と名前しか登録が無く、
これが無いとどの語でも見つからなかった。道路や縁石は建物ではないので出ない。
実測で「木」は、1km で 6.8 秒・3 件、5km で 19.2 秒・19 件、どちらにも
創成材木店が入った。

**唯一、本当の部分一致（正規表現）ができる**ので残してある。ただし遅く、
断られやすい。実測で、同じ問い合わせを続けて投げると 3 回目には 429 が返り、
しかも**返ってくるまで 9.5 秒**かかった。公開ミラーもほとんど死んでいて、
`kumi.systems` / `private.coffee` / `monicz.dev` は接続はするが 30 秒待っても
無言、`overpass.osm.ch` は 0.9 秒で返るが**スイスのデータしか無い**。
生きているのは `overpass-api.de` とその別名 `lz4` `z` の 3 つだけだった。

### 試して落とした先

- **国土地理院の地名検索**（`msearch.gsi.go.jp`）は **0.4 秒**と非常に速いが、
  **位置で絞る手段が無く全国から返ってくる**。「山岳」で青森・神奈川・長野の
  山が並ぶので、「ここから 2km」を出すこの画面には使えなかった。
- `overpass.osm.ch` は速いがスイス専用。

### 承知しておくこと

- **収録は Google マップとは違う。** 日本ではコンビニ・チェーン店・駅は厚いが、
  個人店や新規開店、ビル内のテナントは薄いことがある。
- **3km より遠くを、言葉なしで見るときは「目印になるもの」だけ**を取りに行く
  （山・駅・観光地・城・大きな病院・大学）。8km 先のコンビニは目印ではない。

## キーを入れるという選択

**API キーは本来アプリの作者のもので、利用者のものではない。** 他のアプリで
キーを入れずに Google の結果が出るのは、作者のキーがアプリに埋め込まれて
いるか、作者のサーバ経由で呼ばれていて、**課金を作者が負担している**から。
mawary には作者側の課金アカウントもサーバも無いので、入れるなら自分のキーに
なる。公開リポジトリにキーを置けば抜かれて悪用されるだけなので、埋め込まない。

キーを入れると、応答は 1 秒を切り、中身は Google マップそのものになる。
とはいえ**キー無しでも待たされない**ところまでは来ているので、取らない方針なら
そのままで構わない。
（Google Maps Platform には月ごとの無料枠があり、個人利用なら収まることが多い。
課金が有効なキーが要るので、現在の料金は Google の料金ページで確かめてほしい。）

**Google Places API (New) を使いたいときだけキーを入れる。** 入れれば
そちらが優先され、Google マップの検索結果がそのまま出る。渡し方は 2 通り。

- `local.properties` に `MAWARY_PLACES_API_KEY=AIza...` と書いてビルドする
- **歯車ボタン**から設定画面を開き、「Google Places API キー」の欄に貼る（端末内に保存され、次からはそれを使う）

Google が断ったときも Overpass に落ちる。どちらから取ったかは設定画面の一番下に出る。

取りに行くのは、**持っている答えが無いか古くなっているとき**で、かつ
**前回から距離レンジの 1/4 以上動いたとき**か、**検索の言葉やレンジが変わったとき**。
通信は最低優先度のスレッド 1 本で、**前の取得が終わっていないうちに来た依頼は
捨てずに預かり**、空き次第すぐ走らせる（遅い Overpass を待っている間に
検索語を入れると、その検索が黙って消えていた）。
持っている答えをもう一度渡すことはしない。止まっていても位置の更新は届くので、
渡し直すと画面が描き直され、**一覧のスクロール位置が飛んでしまう**。

## 実測

Sony XQ-FS44 / Android 16 (API 36) で測った値。

| 測ったもの | 値 |
| --- | --- |
| APK の大きさ | **58.6 KB** |
| 冷えた状態からの起動 (`am start -W` の TotalTime) | **96 ms** |
| **据え置いて 20 秒の描画枚数** | **0 枚**（v2 までは約 1080 枚） |
| 操作し続けたときの描画 50 / 99 パーセンタイル | **5 ms / 8 ms** |
| 引っかかった frame（同上、1196 枚中） | **5 枚 (0.42%)** |
| Missed Vsync | **0** |
| GPU 50 / 99 パーセンタイル | **2 ms / 4 ms** |
| メモリ (TOTAL PSS) | **約 64 MB** |
| 起動時の「周りのもの一通り」(Photon、キー無し) | **3 〜 4 秒 / 140 件前後** |
| **検索語を入れてから結果が出るまで** | **約 1 秒**（手元から） |
| 検索語を空に戻す | **約 1 秒**（通信なし） |

## 軽いことの中身

- **`onDraw()` で確保しない。** Paint も Path も文字列も、元になる値が
  変わったときにだけ作る。距離と方位は**自分が動いたときにだけ**計算し直す。
  名前を幅に合わせて縮める計算も、一覧の文字サイズを決める計算も、
  取得のたびに 1 回だけ行って持っておく。
- **`onDraw()` の中に、条件で回り続けるループを置かない。** ラベルの重なりを
  避ける処理にも回数の上限を入れてある。メインスレッドの暴走で一度痛い目を
  見ているため。
- **ほとんど塗らない。** 影もグラデーションも無く、線と短い文字列だけ。
  塗ってあるのは方位磁石の針と本体だけで、そこは一目で読めることの方が大事だから。
- **ライブラリを足さない。** 通信は `HttpURLConnection`、JSON は Android に
  入っている `org.json`、現在地は `LocationManager` を直に使う。
  そのぶん APK は 59 KB で済み、起動に読み込む物も無い。
- 画面を離れると**センサと位置の購読を両方切る**ので、裏に回ると何もしない。

## 権限について

要るのは 2 つだけ。

- **`INTERNET`** — 周りに何があるかを尋ねるため。
- **`ACCESS_FINE_LOCATION`** — このアプリは方位と距離しか出さないので、
  現在地がずれると**全部の杭がずれる**。おおよその位置は街区ひとつ分の幅があり、
  レンジ 100m では使い物にならない。

`ACCESS_COARSE_LOCATION` は**宣言していない**。Android 16 で実測したところ、
`ACCESS_FINE_LOCATION` だけを宣言しても許可ダイアログには
「正確な位置 / おおよその位置」の両方が出て、**「おおよその位置」を選ぶと
宣言していない `ACCESS_COARSE_LOCATION` の方が付与される**。
そのため、おおよその位置しか貰えなかった場合もアプリは動くようにしてある
（杭の位置はそのぶん甘くなる）。

位置情報を外へ送るのは**周辺検索の問い合わせだけ**。履歴も保存しない。

## 表示の言語

**日本語で固定。** 多言語対応はまだ考えていないので、`values/` を日本語そのものと
して扱い、`values-ja/` は作っていない。分けた瞬間に英語版の面倒を見ることになり、
いまはその面倒に見合うものが無いため。
方位も `北 / 北東 / 東北東` のように日本語で出す。

## 作り方

Android SDK (platform 36 / build-tools 36) と JDK 17 が要る。

```sh
# 署名鍵を作る（初回だけ）
keytool -genkeypair -keystore keystore/mawary.jks -alias mawary \
        -keyalg RSA -keysize 2048 -validity 10000 \
        -storepass <パス> -keypass <パス> \
        -dname "CN=mawary, OU=mawary, O=mawary, C=JP"

# keystore.properties を置く
#   storeFile=keystore/mawary.jks
#   storePassword=<パス>
#   keyAlias=mawary
#   keyPassword=<パス>

./gradlew assembleRelease
```

出来上がりは `app/build/outputs/apk/release/app-release.apk`。
`keystore/` と `keystore.properties` と `local.properties` は
リポジトリに入れていない。
